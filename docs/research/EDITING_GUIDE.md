# Editing guide

The website is the executable source of truth. The bundled Figma plugin is an editable visual handoff generated from the same design direction; it is not required to publish the site.

For the shortest Codex/Figma workflow, start with `../CIBA_STYLE_WORKSPACE.md`.

## Edit content without touching layout code

- Artist name, statement, CV, optional email/CV download, location, and social links: `src/content/site/profile.json`
- One JSON file per work: `src/content/projects/*.json`
- Palette, type stacks, motion timing, workspace height, and every window's x/y/width/rotation/z: `src/content/art-direction.json`
- Approved public media files: `public/assets/projects/<slug>/`; reference them with
  `/assets/projects/<slug>/...` paths in project JSON. Unpublished or superseded source belongs
  under `source-archive/`, never under `public/`, because Astro deploys every public file even
  when no page links to it.

Every public project needs localized `zh` / `en` / `ja` tags, image alt text, captions where
shown, evidence details, and at least one body paragraph in all three languages.
Set `published` to `true` only when its facts and evidence are ready; unpublished records remain in
the repository but do not generate public routes. The site builds all three language routes from
the published records.

Use a neutral project hierarchy: title, year, medium/tools, current status, then one or two plain
sentences describing the concept. Avoid claims that the work or website is beautiful, immersive,
easy to understand, or curator-friendly. See `2026-07-18-artist-portfolio-copy.md` for the sourced
copy rule.

## Add a project

1. Duplicate one project JSON file and choose a unique `slug`.
2. Fill year, medium, status, priority, featured state, localized tags, palette, localized media
   descriptions, optional links, and all three translations. Professor-facing public records must
   also show role, scale/encounter format, and credits. If a fact is not verified, use an explicit
   localized “artist verification pending” value instead of inventing or silently omitting it.
3. Add a position with the same slug under `workspace.positions` in `src/content/art-direction.json`. If omitted, the site supplies a safe fallback position.
4. Run `npm run check:design`, `npm run check`, `npm test`, `npm run build`, and
   `npm run check:built`. The built-site check rejects any public file outside the reviewed
   deployment allowlist.

The standard detail page renders the first media item as the hero and all remaining items as a gallery. `play` and `archive` links are both supported.

## Change visual direction

Edit `src/content/art-direction.json` first. CSS variables are generated by `src/lib/art-direction.ts` and applied globally. Structural design rules live in `skills/ciba-art-direction/references/aesthetic-system.md`; explicit feedback can be appended with the skill's `scripts/add_taste_observation.py`.

## Editable Figma handoff

Follow `figma-export/README.md` to import the local plugin. It generates editable text, shapes,
media placeholders, design tokens, and five independent Works windows. Website interactions such
as real drag bounds, filtering, routing, and reduced-motion behavior remain in code.

## Local preview

```bash
npm install
npm run dev
```

Append `?motion=reduce` to any local route to preview the same static composition used for the
OS-level reduced-motion path, for example `http://localhost:4321/zh/?motion=reduce`.

Before publishing:

```bash
npm run check
npm test
npm run build
npm run check:built
```

Before a formal submission, replace the visible role/credits verification notes with confirmed
facts and add a real email, CV download, playable-build URL, and final artwork media where
applicable. Optional links stay hidden until supplied, so unfinished placeholders never produce
broken public actions.
